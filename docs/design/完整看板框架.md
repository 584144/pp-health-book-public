# PP's 健康簿｜完整看板框架 README

> 版本：v1.0｜2026-11-07  
> 用途：交给 Codex / 开发人员，基于**现有健康簿增量开发**。本文件是产品信息架构、交互规则及验收说明，不代表现有功能均已实现。

## 1. 产品目标与原则

- **按访问频次排序导航**：今日 → 生活方式 → 健康趋势 → 女性健康 → 医疗总档案 → 体检计划；不要自行改动顺序。
- **每天一次自然语言对话**：用户用一句或一段话口述饮食、运动、皮肤情况、补剂、疲劳等；AI提取并更新相关模块。无需拍照识别食物，不强制逐餐打卡。
- **今日保持极简**：只展示「今日记录」与「今天最值得做的事（最多3条）」。不再增加独立待办、异常提醒等卡片；必要信息可以融入这两处。
- **数据只维护一处，多处引用**：化验、周期、运动、补剂等可在不同模块参与分析，但不得复制出多份相互独立的记录。
- **复用现有能力**：优先读取既有 Apple 健康/手表、体重体脂秤、周期、化验报告、病历等；不重复录入、不重构已有医疗系统。
- **避免过度工程化**：日常手动记录按日期保存结构化内容及必要备注即可，不要求每个字段单独建立复杂的时间戳、来源或置信度系统；但检查报告日期、处方有效期、补剂剂量等影响判断的关键资料必须保留。
- **医学边界**：建议用于健康管理，不替代诊断；不得将关联性表述为因果，不用单次家用体脂数据或HRV直接下诊断。

## 3. 各分支细则

### 3.1 今日

**今日记录**：提供一个自然语言对话入口；用户可一次性口述全天事项。AI识别日期、饮食、运动、皮肤变化、补剂实际服用、睡眠感受及其他症状，生成简洁摘要并写入对应模块。允许查看、修改、撤销；同日再次补充应更新对应记录，避免重复计数。未提及的内容标为「未记录」，不能自动当作「未发生」。设备数据照常自动同步，不依赖每日对话。

**今天最值得做的事**：最多3条，按健康意义、近期目标、可执行性排序；可以包含已有护理或补剂提醒，但不另设复杂待办区。建议简短并能解释原因；没有值得推荐的事项时允许少于3条。

**对话示例**：「早餐还是平时的杂粮米糊和鸡蛋；午餐牛肉饭，晚餐三文鱼和青菜；今天打网球一小时，有点累；下巴长了两颗痘；鱼油和D3都吃了。」→ 自动拆分到饮食、运动、皮肤、恢复、补剂模块；必要时追问关键歧义，避免冗长问卷。

### 3.2 生活方式

#### A. 护肤美容

- **皮肤状态**：记录出油、干燥、下颌痘、黑头、泛红/敏感等，按周/月查看变化；用户口述即可，照片非必需。月经周期、睡眠、饮食只能作为相关性线索。
- **日常护肤**：早晚步骤、保湿、防晒；按实际皮肤状态、季节和产品耐受调整。防晒建议基于日晒暴露，不以减少防晒作为补充维生素D的手段。
- **功效护理**：刷酸、去角质、面膜、去黑头等；记录上次使用和适当的下次提醒。可选护理不强制周期打卡；注意刺激性成分叠加，避免过度清洁。
- **医美项目**：项目名称、日期、机构/医生、术后注意事项、医生建议的后续安排；不自动推荐再次注射。
- **产品库**：名称、类别、核心成分、使用方法、开封日期、在用/停用状态；提醒潜在叠加刺激和重复购买。周期阶段只作参考，不机械切换护肤成分。

#### B. 运动健身

- **运动概览**：自动汇总手表的次数、时长、类型、活动能量、步数，与过去4周比较。
- **训练计划**：支持减脂、增肌、力量、心肺、网球表现等目标；按每周训练次数和个人恢复情况安排，不强制按月经周期固定降档。
- **训练记录**：运动类型、时长、主观强度；力量训练支持动作、重量、组数、次数，允许一句话补录；记录运动后不适或疼痛。
- **身体成分**：体重、体脂、腰围、肌肉相关估算值的趋势；过滤明显异常的体脂秤读数，不根据单日波动调整热量。关注力量和围度，不将降低体重作为唯一目标。

#### C. 营养饮食

- **每日饮食**：用户文字/语音口述食物与大致份量；不要求拍照。允许修改AI估算；缺少份量时使用合理区间，不伪装成精确热量。
- **综合营养分析**：统计蛋白质、碳水、脂肪、纤维、蔬果、钙、铁、维D等；同时读取「用药管理 → 补充用药」中**当天确认已服用**的产品和具体营养成分，区分「食物摄入」「补剂摄入」「合计估算」。未确认服用不得默认已摄入。
- **常吃食物库**：保存常用早餐、杂粮米糊等配方及份量；支持「早餐老样子」直接调用，减少重复估算。
- **每周复盘**：看饮食多样性、长期不足风险、蛋白质和纤维等趋势，给出具体食材建议；避免单凭口述估算认定营养缺乏。维生素A、D等重复摄入需提示风险，尤其区分鱼油与鱼肝油。

#### D. 睡眠恢复

- **睡眠概览**：昨晚及7/30天睡眠时长、入睡/起床时间、规律性、工作日与休息日差异；睡眠阶段仅参考，不作诊断。
- **身体恢复**：结合HRV相对个人基线、静息心率、近期运动负荷、睡眠及主观疲劳，给出「正常 / 值得关注 / 建议减量」等解释性提示；不制造未经验证的精确恢复分数。
- **睡眠洞察**：在数据足够时探索睡眠与运动时间、咖啡因、月经周期、压力等的相关性；每周汇总即可，样本不足显示「暂无足够数据」。观察作息调整后是否改善，避免因果推断。

### 3.3 健康趋势

- **7/30/90天趋势**：跨模块聚合睡眠、运动、体重体脂、腰围、HRV、静息心率、周期等已有数据；避免重复开发每个子模块已有的明细图。
- **目标进度**：用户设置目标、期限和可衡量指标；查看执行率与结果，不以单日数据判定成功或失败。
- **周报**：自动概括主要变化、目标执行、可能相关的生活因素和下周1–3项建议；缺少数据时明确说明。

### 3.4 女性健康

- **周期阶段与建议**：显示当前估计阶段、下次月经预测与不确定性；不将周期预测作为避孕依据。
- **身体数据随周期变化**：观察睡眠、HRV、静息心率、体重及症状与周期的关系，优先使用多周期个人数据。
- **周期症状**：经痛、头痛、乳胀、情绪、疲劳等可选记录；异常或持续加重时提示就医。
- **周期记录与预测**：历史开始/结束日期、长度、规律性及预测。**不设「妇科与乳腺」子模块**；相关检查归医疗总档案。

### 3.5 医疗总档案

- **人体健康图谱**：身体部位导航到相关病历和检查；不适合定位单一部位的指标仍可全局检索。
- **检查指标**：结构化化验值、参考区间、单位换算、历史趋势、异常提示及指标解释；检查结果关联原始报告，不重复维护。
- **检查报告**：体检、专项影像及原件统一归档，可按日期/类别查找；妇科和乳腺报告也在这里。
- **就诊记录**：医院、科室、日期、诊断、医生建议及关联检查、处方。
- **用药管理 → 处方用药**：医生处方、剂量、频率、疗程、注意事项、开始/结束状态。
- **用药管理 → 补充用药**：鱼油、鱼肝油、维生素D3等的具体产品、每份成分、剂量、服用频率、实际服用记录、使用目的及必要的复查建议。补剂不在生活方式里再建独立管理页，但饮食模块读取其营养贡献；提醒可在今日建议中出现。

### 3.6 体检计划

- **复查提醒**：关联已有异常指标、医生建议及检查日期；显示预计时间与完成状态。
- **下次体检清单**：结合年龄、病史、家族史和既往结果生成候选清单，说明依据，避免不必要的检查；需医生判断的内容明确标注。
- **已完成**：保留历史计划与完成记录，链接对应医疗报告。

### 3.7 头像菜单

- **个人档案**：基础信息、血型、身高、疫苗、家族史等低频内容。
- **家庭成员与权限**：按成员隔离健康数据；生活方式模块目前仅本人可见，父母默认隐藏。
- **数据同步**：展示Apple健康、手表、体脂秤等连接状态和最近同步情况。
- **导出数据**：允许按个人导出记录与报告，避免跨成员泄露。

## 4. 跨模块联动规则

| 来源 | 使用位置 | 规则 |
|---|---|---|
| 补充用药 | 营养饮食、今日、体检计划 | 仅将确认已服用的营养素计入当天综合摄入；检查重复剂量 |
| 月经周期 | 睡眠洞察、皮肤状态、运动建议 | 作为个人规律分析的辅助变量，不强制执行固定方案 |
| Apple Watch/健康 | 运动、睡眠恢复、健康趋势 | 自动读取，允许缺失；不重复手录 |
| 体重体脂秤 | 运动健身、健康趋势 | 观察趋势，剔除明显异常值，避免单次结果驱动建议 |
| 化验指标 | 医疗总档案、饮食、补剂、体检计划 | 原始记录只在医疗总档案管理，其他位置引用 |
| 每日AI对话 | 今日及生活方式各页 | 一次解析、按类别更新、支持更正/撤销 |

## 5. 最小数据与交互要求

- **每日对话记录**：`日期、原始口述、AI整理摘要、分类条目、确认/修改状态`。分类条目只保存业务所需字段，不给每个营养素或症状强制附加独立元数据。
- **饮食条目**：日期、餐次（可选）、食物、估算份量、估算营养；常吃食物可引用配方。
- **运动条目**：日期、类型、时长、强度；力量训练可选动作/重量/组次。
- **皮肤条目**：日期、部位、状态、备注；无记录不等于无症状。
- **补剂条目**：产品、剂量、成分、计划频率、当天服用状态；计划和实际分开。
- **医疗记录**：沿用现有结构，保留报告日期、数值、单位、参考范围、原件关联等必要医学字段。
- **修改与撤销**：AI一次对话写入的条目应可定位并更正或撤销，撤销后相关汇总同步更新。
- **防重复**：同一份设备同步记录、检查报告或当日补充口述不应重复计数。

## 6. 开发优先级

**P0：** 六大一级导航及顺序；今日一次对话录入与修改撤销；复用现有数据；医疗总档案合并；用药管理分为处方用药和补充用药；生活方式权限隔离。

**P1：** 护肤/运动/饮食/睡眠恢复四个页面；常吃食物库；补剂与营养综合摄入联动；健康趋势7/30/90天与周报。

**P2：** 更深入的周期-睡眠-运动关联洞察、护肤效果对照、个性化体检建议优化。数据不足时不强行输出结论。

## 7. 开发验收清单

- [ ] 一级导航顺序严格为：今日、生活方式、健康趋势、女性健康、医疗总档案、体检计划。
- [ ] 今日仅有「今日记录」「今天最值得做的事」两大区块，建议最多3条。
- [ ] 每天一次口述可同时更新饮食、运动、皮肤、补剂、疲劳等记录；无需食物照片。
- [ ] AI生成内容可查看、修改、撤销；缺失信息不会被误记为零。
- [ ] 女性健康不含妇科与乳腺子菜单；相应报告可在医疗总档案找到。
- [ ] 用药管理分为处方用药、补充用药；补剂不另设重复管理入口。
- [ ] 饮食分析能引用实际已服用补剂的营养成分，区分食物、补剂、合计。
- [ ] 睡眠恢复不只是复制手表数据，能显示个人基线与有数据支持的跨因素洞察。
- [ ] 生活方式目前只对本人开放，其他家庭成员默认隐藏且数据隔离。
- [ ] 尽量沿用现有数据库与同步链路，不为日常记录引入不必要的复杂字段。
