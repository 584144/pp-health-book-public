# PP's 健康簿｜生活方式模块 README

> 版本：v1.0 · 2026-11-07  
> 用途：交给开发 AI / Codex 直接实施。基于现有《PP's健康簿 · 生活方式板块框架》扩展，不重建已有健康簿。

## 1. 产品定位与核心原则

在现有健康簿中新增「生活方式」模块，包含**护肤、健身、饮食、睡眠恢复**四个页面，并与「今日健康」「健康趋势」「健康计划」联动。医疗档案保持独立。

**最重要的交互要求：用户每天只需和 AI 对话一次。** 用户用自然语言简单说当天吃了什么、做了什么运动、皮肤和睡眠感受；已有手表、体重秤、月经周期、化验、病历等数据直接读取。AI 从一次对话中抽取多类记录、补齐可推断信息、汇总今日情况，并生成少量真正有用的建议。**不要求拍照识别食物，不要求逐餐打卡，不要求填写复杂表单。**

设计原则：
- **低摩擦**：一次对话完成当天手动记录；页面以查看、一键确认/修改为主。
- **少重复**：直接复用现有数据、账户与同步机制，不重新录入。
- **不过度设计**：不为每个字段建立复杂的来源追溯、可信度评级或版本历史；只保留正常业务所需的记录日期、必要数值和备注。自动同步数据沿用原系统已有结构。
- **不假精确**：口述饮食的热量、营养素仅为粗略估算，可显示范围；不强迫精确称重。
- **建议有依据**：结合近期趋势、个人目标和实际感受；区分观察到的相关性与因果结论。
- **可控可改**：AI 整理后可一键确认、修改或撤销；允许漏记，不催促补全。
- **医疗边界**：不自动诊断、不自行调整药物；涉及异常症状和持续变化时提示就医。

## 2. 信息架构

```text
PP's 健康簿
├── 今日健康（统一首页 / 生活方式摘要卡）
│   ├── 今日状态：睡眠、恢复、活动、饮食、皮肤
│   ├── 今日最重要的 1–3 条建议
│   ├── 今日对话入口 / 一键确认
│   └── 待办与提醒
├── 生活方式
│   ├── 护肤
│   ├── 健身
│   ├── 饮食
│   └── 睡眠恢复
├── 健康趋势（可复用已有图表页）
│   ├── 7/30/90 天趋势
│   ├── 目标进度
│   └── 周报 / 月报
├── 健康计划（可复用已有提醒中心「接下来」）
│   ├── 运动目标
│   ├── 护理计划
│   └── 检查与复查提醒
└── 医疗档案（现有模块，保持独立）
```

如果现有系统已经有「今天」「趋势」「接下来」，**直接扩展现有页面，不创建重复导航**。先仅为当前用户启用生活方式；父母账号保留配置能力，默认隐藏，数据按用户隔离。

## 3. 数据复用与边界

直接复用现有：Apple 健康中的月经周期、周期症状、睡眠、步数、心率、HRV、运动记录；体重和体脂；体检化验；皮肤科病历；用药与补剂记录。不要新增一套相同数据表。手腕温度如未授权则不使用，也不要将其当成可确定排卵日期的证据。

新增的轻量业务数据仅包括：
- `daily_checkin`：用户 ID、日期、当天自由口述原文（可选保存）、AI 提取的饮食/运动/护肤/主观状态摘要、确认状态。
- `meal_summary`：日期、餐次（可选）、食物与大致份量描述、可选估算营养范围；不要求逐种食材克数。
- `skincare_log`：日期、产品或护理动作、皮肤状态、可选备注。
- `training_log`：日期、运动类型、时长、可选动作/组数/重量/主观强度、疼痛备注；优先复用手表记录并去重。
- `goals`：目标类型、目标值或行为频率、开始/结束日期、进度、状态。
- `routines`：周期性护理/提醒事项、上次完成日、建议间隔、下次提醒日、启用状态。
- `product_library`：在用护肤品名称、类别、主要成分、开封日（可选）、使用状态。

上述是**逻辑结构**，开发时可依照现有数据库合并字段/表，不要求机械新增七张表。每条日常记录只需普通的**日期**以支持趋势和提醒；不必对每个数据点保存精确采集时间、来源链、模型置信分、审计版本。医疗数据和已有同步数据保持原有管理规则。必要的权限控制、备份和安全措施不能省略。

## 4. 核心流程：每天一次 AI 对话

### 4.1 交互示例

用户输入：

> 今天早上吃了鸡蛋和豆浆，中午牛肉饭加青菜，晚上三文鱼和红薯；下午打了一个小时网球。今天下巴又冒了两颗痘，感觉有点累。

系统自动执行：
1. 读取今天已有的睡眠、活动、周期、体重等信息，不要求用户重复报告。
2. 将口述解析为饮食摘要、网球运动（若手表已有同场运动则合并）、皮肤状态和疲劳感。
3. 对不明确的食物份量保留粗略描述，**不编造精确热量**；必要时给出估算范围。
4. 将结果汇总为一张「今日记录」卡片，让用户一键确认；不确定且会影响建议的关键信息，最多追问一两个问题，允许跳过。
5. 更新今日健康、趋势和目标进度，给出最多 1–3 条优先级最高的建议。

**交互约束**：用户不需要每餐都对话；可在晚上一次性回顾全天；不要求食物照片。若用户当天没有输入，自动同步数据仍照常显示，手动记录保持空缺，不当作“零摄入/零运动”。允许隔天补录，并按实际发生日期归档。

### 4.2 AI 输出建议格式

```text
今日已整理
饮食：鸡蛋、豆浆、牛肉饭、青菜、三文鱼、红薯
运动：网球约 60 分钟（与手表记录去重）
皮肤：下颌新发痘痘约 2 颗
感受：疲劳

今日提醒（最多 3 条）
- 今天有运动，晚餐注意蛋白质和充足进食。
- 如果疲劳明显，明天训练可适当减量。
- 记录下颌痘痘变化，不必仅凭周期自动更换护肤品。

[确认记录] [修改] [撤销]
```

## 5. 页面需求

### 5.1 护肤

四块内容：
- **今日方案**：早晚基础护理顺序，重点是清洁、保湿、防晒；功效成分按现有产品、耐受和实际皮肤状态建议。
- **护理日程**：面膜、去角质、美容院/医美项目等可选事项；记录上次、间隔、下次，一键「已完成」。不要默认把面膜、磨砂或去黑头设成必须完成的周期任务。
- **产品库**：产品名称、类别、主要成分、使用状态、可选开封日期；提示明显的叠加刺激风险（如 A 醇与酸类同晚叠加）。
- **皮肤状态**：口述记录出油、干燥、泛红、痘痘部位和数量、黑头；可选上传对比照，但**不是日常必需流程**。

月经周期、季节和天气仅作为参考，不要按固定周期强制切换 A 醇、酸类或训练安排。观察多周期规律后再提示可能关联。皮肤病或医美复诊由医生建议决定。

### 5.2 健身

- **运动概览**：周训练次数、总时长、运动类型、步数、活动能量、近 4 周趋势。
- **身体成分**：体重 7 日平均、体脂长期趋势、腰围（可选每 2–4 周）；剔除明显异常的家用体脂读数，避免把单次测量当成真实变化。
- **目标管理**：支持减脂、增肌、维持体重、提高力量/心肺/网球表现；默认不强推减重。
- **力量训练**：可选记录动作、组数、重量、次数；一句话即可补录，不强制详尽记录。
- **恢复与负荷**：结合睡眠、HRV/静息心率个人趋势、近期训练量、疲劳与疼痛，给出「常规 / 适当减量 / 休息」的建议。不要只凭单日 HRV 决定训练强度。
- **周期适配**：以实际症状、疼痛和体感为主，月经周期只作辅助参考。

安全要求：体重正常者不默认采用每周下降 0.5%–1% 的减重速度；不以“摄入不低于基础代谢”作为唯一安全阈值；若出现月经异常、明显疲劳、持续疼痛、睡眠恶化等，提醒调整计划并考虑就医。腰背不适时避免自动安排高负荷动作。

### 5.3 饮食

- **主要输入**：每天一次口述全天吃了什么；AI 解析食物类别、餐次（可选）和大致份量。
- **今日摘要**：大致热量区间（可选）、蛋白质摄入是否大致足够、蔬菜水果、全谷物、饮水、饮食多样性；避免制造伪精确数字。
- **每周复盘**：蛋白质来源多样性、鱼类/豆类/蔬菜/水果/全谷物摄入频率、膳食纤维、钙等值得关注的营养方向。
- **饮食建议**：优先提供家常食材替换和下一餐可执行建议，不强制每日严格计算卡路里。
- **化验联动**：维 D、血红蛋白、铁蛋白、血脂、血糖等只用于风险提示和饮食建议；不凭单个结果诊断缺乏。
- **补剂**：复用现有用药/补剂模块，避免重复录入和重复服用；不自行建议高剂量补充。

口述不足以估算份量时可以只记录食物种类，不必追问克数。未记录的餐次为“未知”，不是“没吃”。

### 5.4 睡眠与恢复（新增）

- 睡眠时长、7 日均值、入睡/起床规律、夜间醒来情况（若设备支持）。
- HRV、静息心率相对个人基线的变化；只展示趋势，不做疾病诊断。
- 每日主观状态：精力好 / 一般 / 疲劳，可从当天对话提取。
- 咖啡因摄入时间、晚间作息、压力感受：**仅在用户主动提及时记录**，不增加固定打卡题。
- 睡眠不足时，适当调整训练建议；不将粗略“睡眠债”作为医学诊断。

## 6. 首页、趋势与计划

### 今日健康
一屏展示：昨晚睡眠、今日活动、饮食摘要、皮肤状态、当前目标进度、到期提醒；突出「今天最值得做的一件事」。没有数据时显示“未记录”，不展示虚假健康评分。

### 健康趋势
支持 7 / 30 / 90 天：体重趋势、运动频率、睡眠规律、目标完成率、皮肤状态变化、饮食多样性。周报重点回答：**做了什么、有什么变化、下周改一件什么事**。月报用于复盘目标，而非堆砌指标。

### 健康计划
沿用现有「接下来」提醒中心，统一显示训练计划、护肤可选护理、复查/检查提醒。支持一键完成、推迟、关闭；避免多个页面重复提醒。

## 7. 跨模块联动规则

| 触发条件 | 处理方式 |
| --- | --- |
| 连续睡眠不足 + 主观疲劳 | 提示优先休息，训练视状态减量 |
| 力量训练日 | 提醒注意足够蛋白质和整体能量摄入 |
| 体重趋势变化 | 与训练、饮食和周期共同分析，不因两周平台期自动削减热量 |
| 经前皮肤反复变化 | 提示可能关联，持续观察；不强制更换功效成分 |
| 新护肤品后出现刺激 | 提醒检查近期产品变化、减少刺激，持续或严重时就医 |
| 化验指标值得关注 | 提供审慎解释和饮食方向，必要时提醒复查/问诊 |
| 运动后疼痛持续 | 提示减少相关负荷，必要时就医 |

联动建议由规则触发、AI 负责用自然语言解释；不要让模型直接把相关性解释为因果性。

## 8. MVP 实施顺序与验收标准

**第一阶段（必须实现）**
- [ ] 在现有健康簿新增生活方式入口与四个页面。
- [ ] 复用现有健康数据，不创建重复同步链路。
- [ ] 支持每天一次自然语言输入，解析并生成可确认的今日记录。
- [ ] 同一场手表运动与口述运动不会重复统计。
- [ ] 今日健康汇总、7 日趋势、每周简报。
- [ ] 目标设定与进度展示，统一提醒入口。
- [ ] 用户之间的数据隔离；父母账号默认不展示生活方式模块。

**第二阶段（有价值再做）**
- [ ] 护肤产品库与成分提醒。
- [ ] 力量训练动作/组数/重量的简易追踪。
- [ ] 饮食多样性和长期营养趋势。
- [ ] 皮肤状态与周期/作息的关联观察。
- [ ] 月度目标复盘与建议反馈。

**暂不开发**
- 食物拍照识别作为主要入口；逐餐强制打卡。
- 每个数据点的独立精确时间戳、完整来源链、复杂置信度评级或多版本审计系统。
- AI 自动诊断、自动开具补剂剂量、根据周期强制修改护理/训练方案。
- 复杂的综合健康分数、预测性疾病评分。

### 验收场景

1. 用户只说一句「今天吃了牛肉饭和青菜，打了 1 小时网球，睡得不好」，系统能生成饮食、运动、睡眠主观感受记录并让用户确认。
2. 手表已同步同一场网球时，口述不造成双倍运动时长。
3. 未口述饮食的日子，显示“未记录”，而不是 0 kcal。
4. AI 无法判断食物份量时，不生成看似精确的热量数字。
5. 用户可编辑/撤销 AI 整理结果，趋势同步更新。
6. 现有健康数据正常显示，父母账户不看到当前用户的数据。
7. 周报能基于已有数据给出一项具体、可执行的改善建议。

## 9. 给开发 AI 的执行指令

请先检查现有健康簿的技术栈、数据库、同步任务、账户权限、首页及提醒组件。**以最小改动扩展，不要重构现有系统。** 优先实现一次对话完成日常记录的完整闭环，再实现各页面展示。数据模型尽量复用既有表；UI 保持当前项目视觉风格、移动端友好。涉及医学判断的规则采用保守表述。开发完成后说明：改动文件、数据库变更、如何使用每日对话入口、如何运行及验收结果。

**一句话产品目标：每天和 AI 说一次今天的生活，健康簿自动整理、跟踪趋势，并告诉我最值得改善的一件事。**
