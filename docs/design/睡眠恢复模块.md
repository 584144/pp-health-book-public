# PP's 健康簿｜睡眠恢复模块 README

> 开发定位：在现有「生活方式 → 睡眠恢复」页面上增量开发。复用已有 Apple Watch / Apple 健康、运动、女性健康、饮食及每日 AI 对话数据，不另建一套健康系统。

## 1. 目标与边界

本模块不只是重复展示睡眠时长和睡眠阶段，而是回答：**我的作息是否稳定？恢复指标是否偏离个人水平？哪些生活因素与睡眠有关？调整习惯后是否有改善？**

- 优先自动读取已有数据；每天最多一次自然语言对话，允许用户顺带描述咖啡因、疲劳、晚间运动等信息。
- 不强制逐项打卡，不要求拍照，不为每个日常数据额外设计复杂的元数据体系。
- 交叉分析仅表示**关联**，不直接宣称因果；数据不足显示「暂无法判断」。
- 不把 HRV、手表睡眠阶段或自定义恢复状态当作疾病诊断，也不以单一数值决定是否可以训练。

## 3. 各区域功能细则

### ① 睡眠概览

- 顶部卡片：昨晚总睡眠、近7天平均、近30天平均、最近入睡与起床时间。
- 趋势图：7 / 30 / 90天睡眠时长与入睡时间；跨午夜的时间绘图要正确处理。
- 规律性：入睡时间与起床时间的波动幅度，工作日/周末差异；避免把平均睡眠时长等同于睡眠规律。
- 睡眠阶段（REM、核心、深睡）仅作为设备估算的参考展示，不按单晚阶段比例自动诊断睡眠问题。

### ② 身体恢复

- HRV、静息心率分别显示当前值、近7天变化、近28天个人基线和偏离幅度；同一指标尽量保持一致的采样口径。
- 结合最近7天运动时长/强度、最近3天睡眠和每日对话里的疲劳感，显示「无明显偏离 / 需要关注 / 数据不足」。
- 每条提示附简短依据，例如「近3晚睡眠较个人近期平均少约1小时，同时静息心率高于近期常见范围」。
- 不生成未经验证的“恢复分数 82/100”；异常持续或伴明显症状时提示咨询专业人员。

### ③ 交叉分析

| 分析主题 | 数据组合 | 展示方式 | 注意事项 |
|---|---|---|---|
| 睡眠 × HRV/心率 | 前一晚睡眠 + 次日HRV/静息心率 | 睡眠时长分组对比、散点图、趋势说明 | HRV采样时间与口径一致；避免日期错位 |
| 睡眠 × 运动 | 运动类型、时间、时长、强度 + 当晚睡眠 | 网球/力量/有氧/休息日对比 | 样本不足不排名“最佳运动” |
| 睡眠 × 月经周期 | 周期阶段、症状 + 睡眠、HRV、心率 | 分阶段趋势与多周期对照 | 周期阶段可能是估算，不能据此确认排卵 |
| 睡眠 × 咖啡因 | 对话中提及的摄入时间/数量 + 当晚睡眠 | 有/无咖啡因、早/晚摄入对比 | 未提及≠没有摄入；考虑工作压力等混杂因素 |
| 睡眠 × 体重 | 睡眠、体重7日均值、周期、饮食记录 | 同期趋势与简短观察 | 短期体重波动≠脂肪变化，忽略体脂秤异常值 |
| 睡眠 × 次日疲劳 | 睡眠 + 次日口述疲劳/精神状态 | 睡眠区间与主观感受对照 | 未记录主观状态则不推断 |

分析结果优先用自然语言解释**样本量、差异大小、观察时间窗**，不只输出“有相关性”。示例文案必须标记为示例，不可冒充用户实际结果。

### ④ 个人睡眠洞察

- **有利入睡时间范围探索**：比较不同入睡时间段的睡眠时长、次日疲劳、HRV/静息心率，同时提示起床时间和总睡眠时长可能造成混杂；不要声称找到了医学意义上的“最佳入睡时间”。
- **睡眠敏感区间探索**：观察睡眠不足不同小时区间时次日指标的差异；数据不足不生成“阈值”。
- **近期个人规律**：每周汇总最多3条有数据支持的发现，标注「初步观察」或「相对稳定」。
- **改善效果追踪**：可设定“未来30天尽量在23:30前入睡”等习惯目标，对比执行前后睡眠规律、睡眠时长及主观疲劳变化。
- **建议卡片**：每条建议说明所依据的观察，不给出确定性医学结论。

## 4. 数据来源与录入

| 数据 | 来源 | 录入方式 |
|---|---|---|
| 睡眠时长、入睡/起床、睡眠阶段 | 现有 Apple 健康同步 | 自动 |
| HRV、静息心率 | 现有 Apple Watch 数据 | 自动 |
| 运动类型、时长、活动能量 | 现有运动记录 | 自动；漏记时可口述 |
| 月经周期与症状 | 现有女性健康模块 | 自动复用 |
| 体重与体脂 | 现有体重秤记录 | 自动复用；异常值排除 |
| 咖啡因、主观疲劳、晚餐等 | 每日一次 AI 对话 | 可选口述 |

**数据原则**：复用现有记录日期和必要的测量时间（尤其睡眠跨夜、咖啡因与运动发生时刻）；不要求额外增加每条数据的复杂来源/可信度字段。已有数据缺失时显示缺失，不以0填充。

## 5. 日期与分析逻辑

1. 将一次夜间睡眠归属到**醒来的日期**，例如11月6日晚至7日早的睡眠归于11月7日。
2. 分析“前一日运动/咖啡因 → 当晚睡眠 → 次日恢复”时按实际发生时间匹配，不能机械按同一自然日拼接。
3. HRV与静息心率采用稳定口径，先展示原始趋势，再做个人基线比较；建议基线窗口为近28天，可配置。
4. 展示窗口：7天用于概览，30天用于初步趋势，60–90天用于探索交叉关联；**时间窗不是统计可靠性的保证**。
5. 每种对比均展示有效记录天数及各组样本量；样本太少、组别严重失衡或存在明显混杂时只展示描述性数据，不下结论。
6. 月经周期分析尽量比较多个周期的重复现象；不得用手腕温度单独判断排卵。
7. 自动洞察每周更新即可；原始数据随同步刷新。

## 6. 每日 AI 对话示例

用户：
> 今天下午喝了一杯咖啡，晚上打了一个半小时网球，感觉有点累。

系统处理：
- 识别咖啡因摄入（具体时间/剂量未知则保留未知，不擅自补全）。
- 识别网球训练90分钟，若设备已有同一训练则去重。
- 记录主观疲劳，归入对应日期。
- 次日自动关联当晚睡眠数据，用于长期观察；**不因为单次记录就认定咖啡影响睡眠**。

## 7. 页面交互要求

- 默认打开「睡眠概览」，下方切换「身体恢复 / 交叉分析 / 个人睡眠洞察」。
- 所有趋势支持7 / 30 / 90天切换；图表点击可查看日期与实际数值。
- 交叉分析优先显示已有足够数据的主题，缺失主题显示「等待积累数据」，不展示空白复杂图。
- 恢复建议保持简短，最多显示1–2条优先行动；不要把睡眠页做成另一个待办中心。
- 移动端优先，保留桌面端阅读体验；遵循现有健康簿视觉组件。

## 8. 开发优先级

**P0（先上线）**
- 睡眠概览、7/30/90天趋势、入睡/起床规律性。
- HRV与静息心率的个人基线对比、恢复偏离说明。
- 正确的跨夜日期归属、数据缺失处理、现有数据复用。

**P1（有足够数据后）**
- 睡眠×运动、睡眠×月经周期、睡眠×咖啡因交叉分析。
- 睡眠×次日疲劳与体重趋势。
- 每周个人睡眠洞察。

**P2（长期迭代）**
- 有利入睡时间范围探索、睡眠敏感区间探索。
- 生活方式调整前后效果追踪。

## 9. Codex 实施要求与验收

1. **先阅读现有项目结构**：确认 Apple 健康同步、女性健康、运动、体重、AI每日记录的数据表和组件；只做增量开发，不重构整站。
2. 先实现数据映射和跨夜归属，再开发图表与交叉分析；不要虚构缺失数据。
3. 沿用现有权限体系：生活方式板块当前只对本人开放，家庭成员默认隐藏。
4. 复用已有图表、卡片、日期筛选和AI对话入口，避免重复数据库与UI组件。
5. 验收用例至少覆盖：跨午夜睡眠、重复运动记录、缺失咖啡因时间、HRV稀疏采样、月经阶段估计不准、体脂异常值、样本不足、无睡眠数据。
6. 交付时说明：新增/修改文件、使用的数据字段、分析规则、尚未支持的数据来源及如何验证结果。

### 完成标准

- 用户不新增每日手动表单，也能看到睡眠规律性、HRV和静息心率相对基线的变化。
- 有足够数据时能看到至少一种可解释的交叉分析；没有数据时不编造结论。
- 每日一句话可补充咖啡因/疲劳/运动信息，且不重复录入已有设备记录。
- 结果可追溯到实际日期和记录，建议与观察结果相匹配。
